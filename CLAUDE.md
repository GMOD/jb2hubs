# jb2hubs

Monorepo that converts UCSC GenArk and UCSC browser hubs into JBrowse 2 configs,
and serves them via a static website.

This file holds the rules, invariants and traps. The incidents and measurements
behind each one are in `agent-docs/reference/`, named at the end of each
section; read the reference before changing the thing a rule protects.

## Packages

- `website/` — Astro + React static site (pages: search, recently-updated,
  accession, taxonomy, hubs, synteny, etc.)
- `genark2jbrowse/` — scripts + TS that process GenArk hubs into JBrowse configs
- `ucsc2jbrowse/` — scripts + TS that convert UCSC track hubs into JBrowse
  configs
- `hubtools/` — shared TS library used by the converter packages
- `lib/` — shell libraries both pipelines source: `common.sh` (control plane,
  `parse_flags`, rclone sync), `derive.sh` (what decides a derived file's bytes)
  and `chainpif.sh` (chain → PIF), with `*.test.sh` suites beside them that CI
  runs
- `scripts/` — repo-level node utilities (`checkConfigCompat.mjs`,
  `checkPluginUrls.mjs`, `extractSyntenyTracks.ts`) invoked from `package.json`
  and `run.sh`
- `agent-docs/` — design notes, surveys and ADRs, filed per
  `agent-docs/CLAUDE.md`

## Generated files — do not hand-edit

`ucsc2jbrowse/configs/*.json` and `genark2jbrowse` configs are 100% generated by
the shell-script pipelines (`make.sh`, `enhanceConfigs.sh`, `src/*.ts`, etc.).
Never edit them by hand — changes are clobbered on regeneration. To add or
change tracks on a UCSC assembly, edit the source-controlled extension file
(e.g. `ucsc2jbrowse/ucscExtensions/hg38.json`, `ucscExtensions/hs1.json`), whose
`tracks[]` are merged into the generated config by the pipeline; then regenerate
and re-upload the configs.

## Lint, format, typecheck

`pnpm lint:fast` (oxlint, syntactic) → `pnpm lint` (`oxlint --type-aware`) →
`pnpm typecheck` (`astro sync`, then `tsc --noEmit`). The rules live in
`.oxlintrc.json`.

- **No disable comments and no file-scoped overrides are in the tree.** A rule a
  whole directory legitimately violates goes in an `.oxlintrc.json` override
  (`no-console` is off for the CLI and build-script trees that way). Every
  `react/set-state-in-effect` violation so far turned out not to need an effect.
- **`.oxfmtrc.json` must keep ignoring `**/.*-uploaded.json`.** An
  `upload_if_changed` stamp is a byte-exact copy compared with `diff -q`;
  formatting one makes every later run re-upload and invalidate CloudFront.
- **`pnpm format` is oxfmt plus prettier for `**/*.astro` only.** Keep
  `.oxfmtrc.json` and `.prettierrc.json` in sync.
- **TypeScript is 7.x everywhere, and `.astro` frontmatter is not typechecked.**
  Put type-sensitive code in a `.ts`/`.tsx` module the page imports. A
  generated, gitignored JSON imported from a `.ts` needs a declaration in
  `website/src/global.d.ts`, or CI's typecheck fails with `TS2307`.
- **After bumping `tsdown` or `rolldown-plugin-dts`, check `hubtools`' emitted
  `dist/index.d.mts` typechecks**, since a dts emitter degrades quietly.
- **tsgolint validates every `tsconfig.json`:** an `outDir` needs a `rootDir`,
  and `moduleResolution: node` is rejected.

Full record: `agent-docs/reference/TOOLCHAIN.md`.

## The website is a major version ahead of published `@jbrowse/core`

The website and react-msaview 8.x run MUI 9, mobx 7 and MST 6; published core
4.3.0 is on MUI 7, mobx 6 and MST 5. `pnpm-workspace.yaml`'s `overrides` hoist
core onto the newer set, and `patches/@jbrowse__core@4.3.0.patch` renames two
`HelpOutline` icon imports MUI 9 dropped.

- **Delete `overrides`, `patchedDependencies` and `patches/` together** when
  core v5 publishes.
- **Check with a browser, not a build.** Each failure here happens inside an
  error boundary, so a green build proves nothing.
- **Before bumping react-msaview, check its tarball's `@jbrowse/core` and
  `@mui/icons-material` imports against the installed core.** The commands are
  in the reference. The peer warning about core `>=5.0.0-0` is expected.

Full record: `agent-docs/reference/TOOLCHAIN.md`.

## The UCSC pipeline's gates

`ucsc2jbrowse/make.sh` stamps each built assembly with `.trackdb_hash` (the
data) and `.pipeline_hash` (the converter code), and reprocesses when either
differs. `DERIVATION_HASH` does the same one level down for the per-file
derivations `needs_rebuild` gates.

- **Add new inputs to `PIPELINE_SOURCES` without reasoning about whether they
  matter.** Over-invalidating costs one cheap reprocess; under-invalidating
  ships wrong configs indefinitely, and no downstream gate can tell.
- **`DERIVATION_SOURCES` must stay a subset of `PIPELINE_SOURCES`.** A change to
  it re-derives every UCSC track file, about an hour of CPU.
- **Advance `.derivation_hash` by hand only with an argument that covers the
  whole corpus.** Otherwise take the re-derivation.
- **`./make.sh --explain` says what a run would do** and calls the same
  predicates the run calls. Keep it that way: a second copy would be a model of
  the run.
- **`No UCSC assemblies have changed` is not proof a converter change shipped.**
- **genark2jbrowse has no such gate.** It visits every hub every run and
  rebuilds what is stale per file.
- **A derivation over hundreds of inputs that yields zero is a broken run.**
  `downloadNcbiGff.sh`, `prune_stray_configs` and `check-orphan-configs` all
  refuse instead of acting on an empty answer; new gates should too.
- **Under `--experimental-strip-types`, `import.meta.main` is false for a `.ts`
  entry point.** Use `process.argv[1] === fileURLToPath(import.meta.url)`.
- **Anything synced whose bytes depend on the clock turns a change-gated deploy
  into an unconditional one.** `list.json.raw` is excluded from the sync for
  that reason.
- **Drop `xxhsum`'s stderr**, which is a carriage-return progress line that
  swallows the log lines after it.

Full record: `agent-docs/reference/UCSC_PIPELINE.md`.

## Configs are built in one pass

`ucsc2jbrowse/src/buildConfigs.ts` rebuilds `config.json`, `minimal.json` and
`config-staging.json` for every assembly in the genome list on every run.
`genark2jbrowse/src/buildConfigsBatch.ts` does the same for every hub, through
the pure `buildHubConfig`. Both write a file only when its text changed, in
oxfmt's format (`formatJson`).

- **Step order is the published key order.** Add a UCSC step by putting it in
  `STEPS` and saying whether its position matters. A step mutates `ctx.config`
  and never reads or writes `config.json`.
- **Verify a builder change by diffing a scratch build:** `--out-root <dir>`
  writes there and touches nothing else.
- **Text indexing runs after the config is written**, because
  `jbrowse text-index` reads the indexing policy off the track's `textSearching`
  slot.
- **`generateDefaultSessions` precedes `minimalConfig`**, so a minimal config
  keeps the track its own default session opens.
- **`MINIMAL_TRACK_PATTERNS` match a whole `trackId` segment, never a
  substring.**
- **Both walks iterate the genome list's keys**, not the directories on disk.
  Retiring a real config for a db UCSC no longer lists stays manual:
  `check-orphan-configs` fails the upload and does not delete.
- **A derived upstream url that 404s gets a `.notfound` sentinel, only on
  404/410.** A timeout or 5xx never counts as gone, here or in
  `checkIfFileAccessible`, the sidecar mirror or the track-url check.
- **A GenArk-backed UCSC alias names its GenArk twin's PIFs**, so genark
  `make.sh` runs first. Do not dedup an alias by pointing it at the GenArk
  config: the accession page relies on `/ucsc/<db>/config.json` existing.
- **`hubs/` stays committed** so `git diff` after a run shows what changed.
  Nothing reads its history; `genark2jbrowse/hubFirstSeen.json` holds first-seen
  dates.
- **The hub listing refuses under 10,000 hubs**, and `rsync --files-from` must
  stay chunked (4,000 paths).

Full record: `agent-docs/reference/UCSC_PIPELINE.md` and
`agent-docs/reference/GENARK_PIPELINE.md`.

## Old JBrowse versions read these configs

A hub config lives at one permanent url that Desktop installs and published
links keep naming, so a regenerated config has to boot on every host in
`HOST_VERSIONS` (`scripts/checkConfigCompat.mjs`); the oldest entry is the
support floor.

- **`plugins[].url` is the one field that can kill a whole session.** Unknown
  track types, adapters and shorthand cost an old host that one track.
- **An unknown display type is fatal once its track is opened**, and
  `check-config-compat` cannot see it because nothing opens the track. A display
  type newer than the floor is staging-only until a release carries it. Run
  `pnpm check-display-types` before promoting one.
- **Stage a config-level feature in the sibling `config-staging.json`**
  (`stagingEnhanceOptions` in hubtools), never a separate tree: a config names
  its data relatively. GenArk hubs are not staged.
- **Upload staged configs before deploying the staging website.**
- **Run `pnpm check-config-compat` before shipping regenerated configs**, and
  `--plugin Name=path` before publishing a plugin build these configs name.
  `run.sh`'s `gate_configs` runs the checks before either upload;
  `SKIP_CONFIG_GATE=1` overrides.
- **Plugin bundles are published from another repo**, so a config can break with
  nothing pushed here. `config-canary.yml` is the layer that catches it.

Full record: `agent-docs/reference/CONFIG_COMPAT_AND_SIDECARS.md` and
`agent-docs/architecture-decision-records/0002-config-compat-across-jbrowse-versions.md`.

## Assembly sidecars are mirrored on UCSC only

jbrowse-core's `assembly.loadPre()` fetches sequence regions, aliases, cytobands
and genetic codes in one `Promise.all`, and one rejection fails the assembly. So
a UCSC assembly's `chrom.sizes`, `chromAlias` and `cytoBand` are copied beside
its config and named relatively (`hubtools/src/mirrorSidecars.ts`).

- **Do not mirror GenArk.** That sweep was 101,384 objects and was reverted. Do
  not probe GenArk's ~101k sidecar urls in bulk either.
- **Mirroring runs after `ensureAssemblyAliasesAndCytobands`.**
- **A sidecar that 404s is removed from the config; `chromSizes` never is.**
- **`MUST_BE_LOCAL` assemblies may not name an upstream sidecar** even when
  upstream answers (`pnpm check-sidecar-urls`).
- **`chromSizes` is a bare string on TwoBitAdapter**, so anything rewriting
  relative locations has to name it explicitly, as `mergeAll.ts` does.

Full record: `agent-docs/reference/CONFIG_COMPAT_AND_SIDECARS.md` and
`agent-docs/architecture-decision-records/0003-mirror-assembly-sidecars.md`.

## Requests to hgdownload are budgeted

hgdownload is a research file server our users pull from, and it fails by
stalling, not by erroring.

- **`pnpm check-track-urls` is not a sweep:** 300 urls a run, 1 request a
  second, oldest first. Do not raise the budget to finish faster.
- **`--offline` errors without a built dir** instead of passing vacuously.
  Scripts resolve the built dir through `scripts/builtDir.mjs`, because `run.sh`
  does not source `ucsc2jbrowse/common.sh`.
- **Every fetch has a deadline** (`FETCH_TIMEOUT_MS` in `hubtools/src/util.ts`),
  and a transient failure is retried before it counts.
- **`hgdownload2` is a fallback for reads only.** No published config names it.
- **"Not a real assembly" does not excuse a url we publish.**
- **A workflow that fails on purpose must save its cache with `if: always()`**
  (`actions/cache` skips the save on failure), and the canary re-probes every
  url last seen gone outside the budget.
- **`UcscStatusBanner` compares hgdownload against a same-origin control**, has
  a hard deadline, mounts only on launch pages and stays a plain script.

Full record: `agent-docs/reference/TRACK_URL_CHECKS.md`.

## Derived files and the tools that write them

- **`assert_bgzip_toolchain` is fatal in both `make.sh` files.** It compares the
  bytes bgzip emits against `BGZIP_TOOLCHAIN_SIGNATURE`; a different build
  rewrites and re-uploads every derived `.gz`. `ALLOW_BGZIP_DRIFT=1` accepts a
  deliberate change.
- **Every `jbrowse` invocation uses `JBROWSE_CLI`**, the repo's pinned CLI,
  never the one on PATH.
- **A PIF carries a `.cli` stamp, and a CLI bump rebuilds the whole PIF corpus**
  (about 930 GB, re-uploaded). Start that run on purpose.
- **Do not put a command substitution in a per-hub gate.** The liftOver gate
  runs 52,000 times.
- **`save_rebuild_stamp` takes the output and refuses to stamp one that is
  missing or empty.** `pnpm check-tabix-indexes` requires an index beside every
  derived `.bed.gz`/`.gff.gz`.
- **Nothing checks that a derived file holds records.**
  `find $UCSC_BUILT_DIR -size -100c` over the `.gz` files is the cheap version.
- **`addGeneticCodes.ts` reads `chrom.sizes` from the mirrored sidecar on disk**
  and caches NCBI answers in `.mitoCodes.json`, negatives only for taxa NCBI
  actually served.
- **The assembly runners name the assemblies that failed.** A count hides a
  systematic breakage.

Full record: `agent-docs/reference/DERIVED_FILE_INTEGRITY.md`.

## The website deploy and build

- **`website/deploy.sh` unpacks a release, verifies the file count, then swaps
  the webroot symlink.** Nothing is deleted until the new release serves; old
  releases are pruned at the start of the next deploy.
- **tar+zstd, not rsync:** `prebuild` cleans, so every file has a fresh mtime.
- **`astroBuild.sh` collapses astro's per-route log lines** into a counter.
- **`src/lib/searchIndex.ts` declares the `IndexEntry` tuple once**; every
  search box splits a query with `src/lib/searchTerms.ts`.
- **`src/pages/ucsc/launch.astro` turns a UCSC `hgTracks` link into a JBrowse
  launch.** A `formatDetails` callback reads `feature.url`, never
  `get(feature, …)`.
- **`features.staging` gates pages and which hosted build links target**, not
  configs: the configs are one tree served to both sites.

Full record: `agent-docs/reference/WEBSITE.md`.

## The pangenome pages

`/pangenomes/<id>` is one page per graph, rendered by
`website/src/pages/pangenomes/[dataset].astro` from the dataset in
`pangenomeDataset.ts`, and kept to static HTML with almost no prose.

- **Run `website/pangenome-config/upload.sh` before deploying a change to a
  config under `website/pangenome-config/`.** jbrowse-web fetches it from the
  bucket.
- **`pnpm check-pangenome-launches` boots every launch and reads the lanes
  back.** Run it after touching `pangenome*` or a config.
- **`lanes()` in `pangenomeLinks.ts` is the one rule for window width:** segment
  lanes under `MAX_DETAIL_WINDOW_BP`, the coarse tier above.
- **A haplotype the lane track maps to an assembly must be that assembly's
  alias.**
- **The structural forms come from the genome-wide sidecar**
  (`pangenomeSvStates.ts`), for curated loci and the Any region box alike.
- **`features.pangenome` stays staging until core v5**: the graph plugin
  error-pages every released host.
- **A visible change here is owed to the tutorial** in jbrowse-components
  (`website/docs/tutorials/genomes_pangenome.md`).

Full record: `agent-docs/reference/PANGENOME_PAGES.md` and
`agent-docs/reference/PANGENOME_PORTAL.md`.

## The protein browser launches a session the plugins have to agree with

`/protein-browser` (`website/src/components/ProteinBrowser.tsx` and the files
beside it) is the landing page for the "Proteins in the Genome Browser" paper:
gene symbol → collapsed-intron genome view + 3D structure + ortholog alignment,
three views on one transcript model. The design record, including the two
residue↔codon mapping bugs that shipped with every unit test green, is
`agent-docs/reference/PROTEIN_BROWSER.md`. Three things to hold onto:

- **`userProvidedTranscriptSequence` is the transcript's own translation**, the
  NP record of the picked isoform — never the UniProt canonical. The protein3d
  plugin pairwise-aligns it against the structure's residues; handing it the
  structure's own sequence makes that alignment an identity and mis-indexes the
  CDS whenever the isoforms differ. Silently.
- **Structures are asked for, not derived.** `structureSources.ts` reads the
  AlphaFold prediction API (which models exist, at which version, with which
  sequence); p2s_mapper's `fetchExperimentalStructures` reads 3D-Beacons
  filtered to `provider === 'PDBe'`. A url built from `AF-<acc>-F1-model_v6.cif`
  404s for any protein past AlphaFold's length cap (DMD, BRCA2, TTN) and for
  every version bump.
- **`pnpm check-protein-launches` is the test that matters.** It boots each
  example gene in a hosted build and reads the ProteinView back: structure
  ready, `pairwiseAlignment` present, `exactMatch` where the model's sequence
  equals the translation — and, for a chip with a preset focus, the focused
  launch too, reading the MsaView's row count and transcript mapping back. Needs
  a browser and six live services, so it is by-hand, before touching
  `geneStructure.ts`/`proteinSession.ts`/`pfamSeed.ts` and before promoting
  `features.proteinBrowser`.
- **A Pfam seed row is a domain, not a protein, and the session says where it
  starts.** `pfamSeed.ts` puts the translation's own segment into the family's
  seed (InterPro serves it, 4–15 KB) and `proteinSession.ts` sends the residues
  before it as the MsaView's `querySeqOffset`, beside the whole transcript as
  `connectedFeature`. Carrying the whole translation as the row instead costs a
  column of gaps per flank residue in every other row: NOTCH1's EGF seed went
  from 4.9 KB to 174 KB.
- **The map's coordinates are the UniProt canonical's.** InterPro regions and
  PDBe interface residues are on it; the launched transcript's translation may
  be another isoform. `ProteinLaunchCard` carries a focus onto the translation
  (`translationRanges`, the residues the two share, measured against codon
  identity) and sends it as `initialTranscriptResidues`, which the plugin
  resolves onto any structure through its own alignment — haemoglobin's
  mature-numbered chains included. Do not reintroduce `initialSelection` or
  author numbering on the page: both were exact for only some structures. The
  canonical is `GeneStructure.canonical`, read from UniProt, and never the
  translation: MANE is not the canonical for KMT2A, PLEC or TTN, and none has an
  AlphaFold model to say so.
