# Minimal Config Generation

This system creates minimal versions of UCSC JBrowse configs that include only
essential tracks.

`minimal.json` is a filtered copy of the same run's `config.json` — same
`assemblies`, `plugins`, `configuration` and `defaultSession`, fewer `tracks`
(and the surviving ones lose their `category`). That makes it the cheap way to
learn an assembly: `@cmdcolin/jbrowse-plugin-hubs` fetches it, not
`config.json`, when a track references a UCSC genome the session does not have,
which is how a liftOver track's mate genome loads on demand. hg38 is 2.1MB as a
full config against ~300KB minimal, hs1 603KB against 12KB. So keep the two
artifacts generated by the same pass (`make.sh` does), and treat the `tracks`
filter as a product decision about what a mate panel should open with.

## What tracks are included?

The minimal configs include only the following track categories:

- **NCBI RefSeq** - All RefSeq gene tracks (ncbiRefSeq, ncbiRefSeqCurated,
  ncbiRefSeqPredicted, etc.)
- **GENCODE** - All GENCODE gene annotation tracks (gencodeComp, gencodeBasic,
  gencodeLncRNA, etc.)
- **RepeatMasker** - Repeat element annotations (rmsk, rmskJoined\*)
- **Gaps** - Assembly gaps (gap, allGaps, gapOverlap)

All other tracks (comparative genomics, conservation, expression data, ClinVar
and the rest of the variant tracks) are excluded from minimal configs.

## Usage

Minimal configs are not generated on their own. `minimalConfig` is derived at
the end of `src/buildConfigs.ts`, the one pass `make.sh` runs over every
assembly to build its configs:

```bash
node src/buildConfigs.ts "$UCSC_BUILT_DIR" "$UCSC_DOWNLOADS_DIR"
```

It has to be last, or at least after `generateDefaultSessions`: the filter keeps
whatever gene track the config's own `defaultSession` opens, so running it
against a config without a session yet drops that track. That ordering
constraint is spelled out beside the `STEPS` array.

For each assembly it builds, the runner writes a `minimal.json` beside
`config.json`. `make.sh` then copies those to `configs-minimal/<assembly>.json`
alongside the equivalent copy of `config.json` into `configs/`.

## Output

`buildConfigs.ts` prints one summary line per step that did something. As of
2026-08 the run covers 238 assemblies, and hg38 keeps 33 of its 595 tracks.

## Files

- `src/createMinimalConfig.ts` - the track filter and `minimalConfig`
- `src/buildConfigs.ts` - the single pass that derives it last, after the
  default sessions it depends on
- `MINIMAL_CONFIGS.md` - This documentation file
